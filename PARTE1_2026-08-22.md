# Parte 1 — Fundação financeira

Implementação baseada na planilha de orçamento familiar, sem recriar o banco e sem alterar as variáveis do `.env.local`.

## O que mudou

### 1. Saldo inicial e saldo final automático

- Nova tabela `monthly_balances` para registrar um saldo inicial manual por mês.
- O saldo manual funciona como uma âncora.
- Se o mês seguinte não tiver outro saldo definido, o sistema calcula automaticamente o saldo inicial a partir do saldo anterior e das movimentações.
- Nova função `get_monthly_financial_summary(year, month)` retorna:
  - saldo inicial;
  - receitas;
  - despesas;
  - resultado operacional (receitas - despesas);
  - aportes;
  - disponível antes dos aportes;
  - saldo final;
  - quantidade de lançamentos.
- O dashboard passou a mostrar essa lógica e permite definir/remover a âncora do saldo inicial.

### 2. Categorias completas da planilha

O template passa a conter:

- 7 categorias de receita;
- 6 categorias de construção/aportes;
- 10 grandes grupos de despesas;
- 73 subcategorias de despesas.

Foram excluídos do template universal os itens pessoais da planilha, como `empresa` e `CONFRATERNIZAÇÃO ALIEANZ`.

O template antigo é expandido de forma idempotente para contas que já haviam escolhido o template no cadastro. Alguns nomes antigos são normalizados sem quebrar referências de lançamentos.

### 3. Aportes ligados às metas

- `transactions` ganhou `reserve_id`.
- `reserves` ganhou `starting_amount` (saldo-base).
- Valores que já existiam em `current_amount` são preservados como saldo-base na migration.
- Novo aporte vinculado a uma meta atualiza o progresso automaticamente.
- Editar o valor, trocar a meta ou apagar o aporte também recalcula a meta automaticamente.
- A tela de Metas não usa mais botões `+100`, `+500`, `+1000` como fonte principal de progresso.
- O botão `Registrar aporte` abre o lançamento já no tipo Aporte e com a meta pré-selecionada.
- Continua disponível `Ajustar saldo-base` para informar valores acumulados antes do uso do sistema.

### 4. Nova lógica financeira no dashboard

- **Resultado operacional:** receitas - despesas.
- **Disponível antes dos aportes:** saldo inicial + receitas - despesas.
- **Saldo final/disponível:** saldo inicial + receitas - despesas - aportes.

O tipo interno do banco continua sendo `reserva` para manter compatibilidade, mas a interface passa a usar o termo **Aporte** quando se trata de movimentação.

## Migration nova

Aplicar somente:

`supabase/migrations/20260822000002_financial_foundation.sql`

Antes do push definitivo:

```powershell
npx supabase migration list
npx supabase db push --dry-run
```

O dry-run deve listar somente `20260822000002_financial_foundation.sql` como pendente.

Depois:

```powershell
npx supabase db push
```

## Validações realizadas

- `tsc --noEmit`: OK.
- ESLint: 0 erros / 0 warnings.
- O build não pôde ser concluído neste ambiente porque o `node_modules` enviado contém o SWC de Windows e este ambiente Linux não possui acesso ao registry para baixar o binário Linux. O mesmo motivo já ocorreu na revisão anterior; não foi encontrado erro de TypeScript ou ESLint.
- `.env.local`: preservado byte a byte em relação à versão corrigida anterior.

## Testes recomendados após aplicar a migration

1. Abrir o dashboard e definir um saldo inicial para o mês atual.
2. Criar uma receita e confirmar que aumenta o resultado e o saldo final.
3. Criar uma despesa e confirmar que reduz o resultado e o saldo final.
4. Criar uma meta com saldo-base.
5. Em Metas, clicar em `Registrar aporte`.
6. Salvar um aporte vinculado à meta e confirmar que o progresso aumenta.
7. Editar o valor do aporte e confirmar que a meta é recalculada.
8. Apagar o aporte e confirmar que a meta volta ao valor anterior.
9. Avançar para o mês seguinte no dashboard e confirmar que o saldo inicial foi herdado automaticamente.
10. Abrir Categorias e confirmar o template expandido.
